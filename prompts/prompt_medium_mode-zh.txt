# ⛔️ 关键禁令：严禁自然语言证明 ⛔️

**这是本次会话最重要的规则。**

1. **零容忍叙述性注释：** 严禁用注释（`/- ... -/` 或 `--`）写数学推导、计划或自然语言解释。
* **违规示例：** `/- 先证明 x > 0，然后对 n 归纳... -/` -> **禁止。**
* **违规示例：** `-- 我们用定理 X 得到 Y...` -> **禁止。**

2. **注释行数限制：** 单个注释块最多 **42 行**。注释仅用于：
* 标记：`/- (by claude) Helper for [lemma] -/`
* 简短指令：`/- (by claude) Case 1: n = 0 -/`

3. **代码即解释：** 如果步骤复杂到需要解释，就应抽成**新辅助引理**。
* 不要用注释解释，提取为新引理，名称与类型即文档。

4. **注释序列约束：** 禁止连续 **5 个以上** 注释块（`/- (by claude) ... -/` 或 `/- ... -/`）未被有效 Lean 代码打断。

# 新引理追踪（重要）

* 新引理可暂留 `sorry`，之后再证
* 这样可追踪关联工作

## 示例
```lean4
/- (by claude) Helper for main_result -/
lemma helper (n : ℕ) : n + n = 2 * n := by
  sorry

theorem main_result (n : ℕ) : n + n = 2 * n := by
  exact helper n
```

# 其他提示

## 你是数学家，不是枚举器。依赖洞见而非穷举。
1. **禁止 2^N 式组合爆炸：**
* **严禁** 盲目对所有变量做多层 `cases` / `rcases` / `induction` / `fin_cases` 超过 **3 层**，除非有明确数学理由。
* **坏例：** 连续 `rcases a; rcases b; rcases c; rcases d; ...` 产生 16+ 分支。
* **好例：** 用对称性（WLOG）、反证、抽屉原理等同时处理多种情况。

2. **DRY 原则：**
* **严禁** 在各分支重复相同证明脚本。
* **行动：** 逻辑相同就抽成**辅助引理**。
* **行动：** 若存在对称性，用 `wlog` 或对称引理。

3. **避免 `all_goals` 式战术长城：**
* **禁止：** `rcases ... <;> rcases ... <;> ... <;> all_goals (try simp; try linarith ...)` 期望战术霰弹解决大量子目标。
* **要求：** 拆分情形必须有数学必要性（如  与  合理；  通常不合理）。

## 代码结构与重构（关键）
* **避免代码/注释“长墙”：** 若单条语句有长注释或代码过长难读：
1. 拆分：抽出部分逻辑为辅助引理。
2. 清理：抽出后移除长解释性注释。引理结构应自解释。
3. 不要留下巨型注释块；用模块化引理代替文档。

## 证明技巧
* 用 `simp` 时先尝试 `simp [context]`，再用 `simp?` 获取最小集合。
* 禁用 `native_decide`。
* 用 `#eval` 计算表达式。
* 类型转换用 `norm_cast`。
* 多用 `apply` 逐步使用假设，不要长 `exact`。
* 用 `apply?` 查找可应用引理。
* 简单目标可试 `hint` 或 `grind`。
* `hint` 用法：输入 `hint`，编译器给建议，再用建议引理替换。
* `grind` 类似 `omega`/`aesop`，更强。
* 不要在单个 `linarith`/`nlinarith` 里放超过 5 个项。
* 严禁在自然数上随意做除法/减法，除非定理要求；需明确类型，避免未指明类型的字面量运算。
* 涉及分数必须写明类型，如 `((2 : ℝ) / 3)` 或 `((2 : ℚ) / 3)`，除定理原文外都要注明。
* 自然数变量上的除/减也禁止，除非定理要求；需要时先转为 ℤ/ℚ/ℝ。
