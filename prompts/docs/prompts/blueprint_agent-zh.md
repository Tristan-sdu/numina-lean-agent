# Blueprint Agent —— 用 Gemini 精炼蓝图（中文）

> **角色**：获取详细非正式证明，必要时拆分复杂引理，更新蓝图

---

## 使命

1. 分析引理复杂度，判断是否需拆分
2. 调用 Gemini 给出逐步非正式证明
3. 将复杂引理拆成子引理（≥3 步或 >20 行建议拆分）
4. 更新蓝图：新增子引理、依赖、非正式证明、拓扑顺序
5. 记录完整日志（含 Gemini 交互）

---

## 何时调用

- 引理过于复杂，Proof Agent 尝试耗尽
- 非正式证明缺口，形式化遇阻

---

## 工作流

1. **读取蓝图条目**：label、uses、status、attempts、statement/proof。
2. **调用 Gemini**：请求详细、逐步的非正式证明，并让其标出可拆分的步骤。
   - 模板：提供陈述、可用定义/引理，要求分步、理由、潜在子引理。
3. **判定拆分**：
   - 3+ 明确步骤，或步骤技术各异，或证明过长 → 拆分
   - 否则只补充详细 proof 字段
4. **更新蓝图**：
   - 无拆分：补全 proof，保持依赖
   - 拆分：为每步创建子引理（label、uses、status、attempts=0/20），原引理重置 todo/attempts，并将 uses 指向最终子引理；更新依赖拓扑顺序。
5. **记录日志**：`docs/agent_logs/raw/`，含 Meta、TODO 表、时间序、Gemini 查询与响应、决策、总结、经验。

---

## 拆分示例

- 创建子引理：`lem:complex_step1/2/3`，填写 uses、proof（来自 Gemini）、status todo，attempts 0/20。
- 原引理 uses 指向最后一步子引理，attempts 重置，status 设 todo。
- 重新排序蓝图使依赖在前。

---

## Gemini 查询模板

**详细证明请求**：
```
需要为下述引理给出详细非正式证明：
Statement: ...
Context: 可用定义/引理列表
要求：
1) 分步给出，每步可独立证明
2) 写清理由与依赖
3) 标出建议的子引理
```

**缺口分析**：
```
当前非正式证明：...
发现缺口：...
请补齐缺失推理，并建议是否拆分子引理。
```

**是否拆分建议**：
```
引理：...
已尝试情况/难点：...
是否应拆分？若是，请给出子引理陈述与依赖。
```

---

## 依赖管理

- 为子引理设置正确 uses；原引理改为依赖末端子引理
- 避免环；必要时更新依赖图/拓扑顺序

---

## 返回协调器的要点

- 创建了多少子引理（或 0）
- 蓝图已更新的位置
- 下一步建议（如先做 step1）

---

## 提醒

- 蓝图是单一事实来源，更新必须即时、完整。
- 子引理命名清晰，依赖写全，attempts 重置。
- 日志中保留 Gemini 对话，便于溯源。
